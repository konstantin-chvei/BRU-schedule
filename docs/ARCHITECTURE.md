# Расписание — архитектура и поведение

Приложение строится как Kotlin Multiplatform + Compose Multiplatform: shared-код содержит домен, парсеры, БД, MVVM и весь UI; Android/iOS предоставляют только SQLite-драйвер и HTTP-engine. Университет выбирается на главном экране. Источник БРУ имеет отдельный каталог/адаптер; пользовательские вузы подключаются по прямой HTTPS-ссылке на открытую HTML-таблицу. Остальные структуры, JavaScript-календари и сайты с авторизацией требуют отдельного проверенного адаптера.

## Что найдено в примерах `bru/`

Проанализированы сохранённые страницы `rasp.bru.by` из корневой папки `bru/`:

- `bru/8.html` — страница группы дневной формы. На каждый отрезок расписания есть `.week-header` и `table.schedule-table`; первая ячейка строки `.time-col` задаёт номер пары и интервал, заголовки `th` содержат день и дату в `small`. В таблице используются карточки `.lesson-card`.
- `bru/4.html` и `bru/6.html` — корневые каталоги дневной/заочной формы; они ведут на каталоги факультетов. `bru/1.html` и `bru/7.html` — уже страницы факультетов, где `a.group-link` ведут на расписания конкретных групп. Дневная форма использует rolling URL вида `..._weeks_YYYYMMDD_YYYYMMDD.html`; заочная форма может содержать `_session_`.
- `bru/5.html` — каталог преподавателей; `a[href*="/teachers/"]` открывают страницу преподавателя.
- `bru/2.html` — расписание занятости преподавателя. Внутри той же недельной таблицы применяются `.occ-card`: `.occ-line1` — тип, `.occ-line2` — предмет, `.occ-line4` — аудитория, `.occ-line5` — дата и время. Дата в `.occ-line5` особенно полезна как точная подсказка для парсера.
- Для адаптивной версии сайт дублирует те же занятия в `.mobile-schedule`. Парсер читает только десктопную `table.schedule-table`, чтобы не сохранять одну пару дважды.

В образце сайта цвет CSS не всегда совпадает с упрощённой цветовой легендой пользователя: `.lesson-lecture` — синий `#3788d8`, `.lesson-practice` — зелёный `#28a745`, `.lesson-lab` — жёлто-янтарный `#e0a800`, `.lesson-pe` — красный `#dc3545`. Поэтому классификатор сначала доверяет семантическому классу/подписи, затем использует цвет как fallback. Это предотвращает ошибку, когда красная физкультура становится «лабораторной», а жёлтая лабораторная — «практикой». В интерфейсе исходные цвета заменяются на индиго, коралл, янтарь и нейтральный серый; исходный CSS сохраняется отдельно для диагностики.

## Структура shared

```text
shared/src/commonMain/
├── kotlin/com/example/bruschedule/
│   ├── App.kt                         # Compose root, навигация, ViewModel factory
│   ├── data/
│   │   ├── AppGraph.kt                # сборка production-графа
│   │   ├── local/SqlDelightScheduleRepository.kt
│   │   ├── remote/                     # Ktor transport, каталоги и rolling URL resolver
│   │   ├── scraper/                    # Ksoup: расписание групп и преподавателей
│   │   └── settings/                   # KMP Settings: parser/schema markers и внешний вид
│   ├── domain/
│   │   ├── model/                      # ScheduleProfile, Lesson, AcademicTask, sync state
│   │   ├── repository/                 # контракты local/remote/catalog/task
│   │   └── usecase/                    # refresh orchestration и merge strategy
│   ├── presentation/
│   │   ├── ScheduleViewModel.kt        # состояния, действия, вычисление карточек/дедлайнов
│   │   └── ui/                         # расписание, редактор, задачи, журнал/откат
│   └── ui/theme/                       # тёмная тема и Theme Mapper
└── sqldelight/.../Schedule.sq          # SQL-контракт и запросы

shared/src/androidMain/                 # AndroidSqliteDriver + Ktor CIO
shared/src/iosMain/                     # NativeSqliteDriver + Ktor Darwin
```

Выбран **SQLDelight**, а не Room: единый SQL-контракт и coroutine Flow работают на Android и iOS без второго persistence-слоя. `KMP Settings` хранит маркер версии схемы, версию формата парсера на профиль и пользовательское оформление; сами миграции БД принадлежат SQLDelight (`.sqm`), а не key-value settings.

## Модели и идентичность пары

- `University(id, name, websiteUrl, sourceType)` хранит добавленные вузы и выбор пользователя; БРУ мигрирует как встроенный источник. `ScheduleProfile` дополнен `universityId`, поэтому списки и расписания вузов изолированы друг от друга.
- `ScheduleProfile(id, type, name, sourceUrl, sourceKey, universityId)` поддерживает несколько групп и преподавателей. Каталог групп БРУ разбирается как дерево «форма обучения → факультет → группа»; результат показывает факультет и сохраняет его стабильную страницу, а не датированный `weeks_...html`. `UniversityScheduleProfileCatalogRepository` маршрутизирует поиск по `universityId`; каталог БГУ параллельно проверяет 10 известных страниц факультетов, следует по ограниченному числу HTML-ссылок расписаний и открывает публичные Google Sheets. Кандидат появляется только если удалось обнаружить код группы в таблице/ссылке и страницу с расписанием; подпись результата содержит факультет и источник. Для остальных вузов пользователь добавляет прямую HTML-страницу.
- Точный код группы останавливает обход дерева сразу после найденного узла. Ошибка на посторонней странице факультета не прерывает поиск; при обновлении устаревшая/ошибочная страница факультета считается подсказкой, и группа повторно разрешается через каталоги дневной и заочной форм.
- `Lesson` содержит обязательные запрошенные поля и дополнительные `lessonDate`, `dayOfWeek`, `slotNumber`, `sourceKey`, `sourceColorHex`. `lessonDate` хранится как ISO `yyyy-MM-dd`, день недели — ISO (пн=1 … вс=7).
- Веб-пара получает стабильный ключ `profile + date + pair/time + index параллельной карточки`. Ключ не содержит редактируемые предмет/преподавателя/аудиторию, поэтому ручное изменение не уничтожает связь с исходной ячейкой.
- `AcademicTask.dueDate` — Unix epoch milliseconds. `profileId` и `subjectNameSnapshot` добавлены как fallback для списка, если сайт позднее удалит пару.
- `AppearancePreferences` хранит тему (`BLUE`, `BLACK`, `WHITE`) и четыре акцента типов занятий; repository оборачивает KMP Settings в `StateFlow` для немедленного обновления Compose.

## Offline-first, синхронизация, слияние и V−1

1. UI подписан на SQLDelight Flow и сразу показывает локальный кэш; интернет не нужен для открытия приложения.
2. Обновление получает актуальную двухнедельную страницу через Ktor, парсит HTML Ksoup и валидирует структуру. Только при явных заголовках «Неделя 1» и «Неделя 2» шаблон разворачивается шагом в 14 дней от текущей даты до конца сессии плюс 7 дней. Базовая граница зависит от выбранного отделения: белорусское — 10.01.2027, российское — 25.01.2027, ИФЗО — индивидуальная дата; для выбранного профиля можно задать отдельный последний день сессии, если сроки факультета отличаются. Экзаменационные страницы без обоих заголовков не повторяются.
3. Расширенные пары коммитятся транзакционно вместе со снимком V−1. Нулевой результат или ошибка оставляет предыдущий локальный цикл без изменений и записывается в журнал.
4. Переданные в БД occurrence-key собираются из исходного ключа слота и конкретной даты, поэтому повторный refresh не создаёт дубликаты и сохраняет ручные правки на той же паре.
5. `ScheduleMergeStrategy` заменяет устаревшие веб-строки новыми, повышает `version`, но custom-строка с совпавшим `id` или `sourceKey` полностью побеждает веб-версию. Ручные пары в свободных слотах остаются отдельно.
6. Задачи не удаляются каскадом при обновлении/rollback. Если занятие исчезло с сайта, связанная задача остаётся в дедлайн-панели с сохранённым названием предмета.
7. Откат восстанавливает веб-часть snapshot и объединяет её с текущими ручными правками; изменения, сделанные студентом после снимка, не затираются.

`ProfileSyncState` содержит последнюю попытку, последний успешный разбор, ошибку и доступность V−1. Экран «Настройки» отображает их и предоставляет действия обновления/rollback. При старте и выборе сохранённого профиля кэш сверяется с актуальным интервалом; при необходимости расписание расширяется либо устаревшие веб-пары за границами интервала удаляются, не затрагивая ручные пары. Ошибка сети не скрывает локальный кэш.

## Парсер и цвета

`UniversityScheduleHtmlParser` направляет профиль в адаптер выбранного вуза. Адаптер БРУ понимает недельные таблицы с несколькими неделями/датами, перенос года на границе декабря/января, карточки `.lesson-card` и `.occ-card`, инлайн-цвет и CSS-правила из `<style>`; directory resolver предпочитает актуальный dated URL. Каталог профилей БГУ просматривает известные страницы Экономического факультета, ФПМИ, Мехмата, Геофака, ФМО, ФСК, Биофака, Института бизнеса, Истфака и Юрфака; по публичным HTML-страницам и ссылкам Google Sheets извлекает коды групп и возвращает кликабельные варианты. На этапе синхронизации адаптер БГУ разбирает HTML-таблицы (в том числе мехматовские с отдельными колонками группы, предмета, преподавателя, типа и аудитории) и публичные Google Sheets через HTML endpoint. В широких Google-таблицах выбирается столбец по коду группы, а пустые ячейки дня/даты и строки преподавателя/аудитории наследуются внутри пары. Время разбирается и с двоеточием, и с точкой; маркеры «ТОЛЬКО dd.mm» и «КРОМЕ dd.mm» превращаются в разовые занятия и исключения из цикла; недельный шаблон расширяется на семестр. Двухнедельное повторение включается только при явных датах, в том числе для листа с одной меткой чётности. Другие структуры HTML, PDF/Excel/DOC, JavaScript-календари и сайты с авторизацией требуют отдельных мобильных адаптеров; backend нет. Тип определяется в порядке:

1. известный CSS-класс занятия;
2. видимая текстовая подпись («Лекция», «Лабораторная», «Практика»);
3. цвет как fallback: синий → `LECTURE`, красный/розовый → `LABORATORY`, жёлтый/зелёный/оранжевый → `PRACTICE`;
4. неизвестные типы сайта (физкультура, экзамен, зачёт и т. п.) → `UNKNOWN`.

`Lesson.colorHex` хранит базовый типовой акцент, `sourceColorHex` — исходный CSS. Compose `LessonThemeMapper` читает выбранную палитру динамически; экран настроек позволяет отдельно выбрать один из восьми аккуратных оттенков для лекций, лабораторных, практик и прочих занятий. `KmpSettingsAppearanceRepository` сохраняет тему BLUE/BLACK/WHITE и цвета в KMP Settings.

## MVVM/UI

- `ScheduleViewModel` объединяет Flow вузов, профилей, занятий, задач и настроек, хранит выбранный вуз/день/профиль/экран, вычисляет «идёт сейчас» и число незакрытых задач. Ежедневная фраза выбирается по локальной дате из GitHub-списка; список обновляется при запуске и хранится в KMP Settings как offline-кэш.
- Главный экран: панель выбора вуза, переключатели его профилей, горизонтальная лента пн–вс и календарь от сегодняшнего дня до границы сессии выбранного профиля + неделя, компактные Bento-метрики и карточки занятий. На расписании есть явные состояния первичной загрузки, фонового обновления, ошибки и локального кэша.
- При добавлении профиля и для старого кэша без семестрового покрытия загрузка запускается автоматически; сохранённые пары остаются видимыми офлайн во время обновления.
- Карточка открывает `ModalBottomSheet`: редактирование пары/создание ручной пары либо создание дедлайна. Все изменения пары сохраняются как `isCustom = true`.
- Панель дедлайнов показывает задачи выбранного вуза и общие задачи без привязки, сортируя их по сроку. Чекбокс меняет состояние локально.
- Настройки объединяют sync journal, обновление/rollback и выбор синей, чёрной или белой темы с редактируемой палитрой пар. Микроанимации есть у переключения экранов и дня недели; по умолчанию остаётся тёмно-синяя тема.

## Сборка и проверка

```bash
bash ./gradlew :shared:allTests
bash ./gradlew :androidApp:assembleDebug
```

Для iOS откройте `iosApp/iosApp.xcodeproj` в Xcode. Для локальной сборки нужны JDK/Android SDK и Xcode (для iOS). `ScheduleCycleExpanderTest` проверяет распознавание только явного двухнедельного цикла, 28-недельное расширение с детерминированными occurrence-key и неповторение ручных пар; `ScheduleArchitectureTest` — парсинг страниц, разрешение групп, приоритет ручных правок и rollback.
