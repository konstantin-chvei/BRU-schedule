# Каталог расписаний GitHub

Приложение больше не ищет группы обходом сайтов факультетов. При нажатии «Найти» оно читает один небольшой CSV-индекс выбранного вуза, кэширует его на 12 часов и фильтрует список локально. При ручном обновлении профиля запрашивается один опубликованный файл расписания с GitHub Pages. Сайты университетов в обычном приложении не опрашиваются.

## Структура опубликованных данных

```text
schedule-data/
├── universities.csv
└── universities/
    ├── bru/
    │   ├── university.json
    │   ├── groups/index.csv
    │   ├── teachers/index.csv
    │   └── schedules/
    │       ├── groups/<profile-id>.html|csv|pdf|xlsx|docx
    │       └── teachers/<profile-id>.html|csv|pdf|xlsx|docx
    └── bsu/
        ├── university.json
        ├── groups/index.csv
        ├── teachers/index.csv
        └── schedules/...
```

`groups/index.csv` и `teachers/index.csv` раздельны для каждого университета. Обязательные поля — `id`, `name`, `schedule_path`, `status`; `subtitle`, `source_key` и `updated_at` необязательны. `source_key` нужен, когда парсеру требуется исходный код группы или адаптер факультета. Для статических профилей преподавателей БГУ указывается точное имя факультета из реестра адаптеров (например, `ФПМИ`); URL сайта приложения не получает.

```csv
id,name,subtitle,source_key,schedule_path,status,updated_at
```

`status=ready` означает, что файл существует и его можно выбрать. `status=missing` оставляет профиль видимым в результатах, но не даёт выбрать его до публикации расписания. `schedule_path` — путь внутри папки этого вуза, например `schedules/groups/mpr-261.html`. Пути автоматически проверяются на обход каталогов.

Расписания в CSV должны содержать даты конкретных занятий, а не повторяемый шаблон:

```csv
date,start_time,end_time,subject,teacher,classroom,type,source_key
2026-10-26,08:15,09:40,"Математика, линейная алгебра",Петров П.П.,203,Лекция,slot-001
```

HTML/PDF/Office-файлы разбираются существующими адаптерами приложения. Веб-версия показывает HTML/CSV-таблицы и открывает PDF/Office как файл.

## Как обновить каталог вручную

В репозитории хранится редакторский реестр источников отдельно от файлов, которые читает приложение:

- `tools/schedules/registry/universities.csv` — список вузов;
- `tools/schedules/registry/<id>/groups.csv` — группы;
- `tools/schedules/registry/<id>/teachers.csv` — преподаватели;
- `local_file` — сохранённый локальный HTML/PDF/Office-снимок;
- `source_url` — ссылка-источник только для скрипта обновления; приложение её не получает;
- `source_key` — необязательный ключ KMP-парсера; он не задаёт сетевой адрес.

1. Добавьте или исправьте строку профиля в нужном CSV-реестре. Укажите постоянный `id`, `source_url` и путь `schedules/groups/...` либо `schedules/teachers/...`.
2. Чтобы обновить уже сохранённые HTML-примеры БРУ офлайн, выполните:

   ```bash
   python3 tools/schedules/discover_bru_profiles.py
   python3 tools/schedules/build_schedule_tree.py
   ```

   Первый скрипт читает только локальные HTML из `bru/`; интернет не использует. Второй создаёт папки вузов, индексы и копирует локальные снимки.

3. Для редкого ручного обновления из зарегистрированных сайтов запустите **только нужный источник**:

   ```bash
   python3 tools/schedules/build_schedule_tree.py --university bru --profile-id mpr-261 --fetch --delay-seconds 2.5
   ```

   `--fetch` обязателен для сетевой загрузки. Запросы выполняются последовательно, с паузой 2,5 секунды между обращениями к одному хосту и повтором только при временном сбое. Не запускайте выгрузку всего списка без необходимости: в реестре могут быть сотни профилей. Если сайт ответил ошибкой, предыдущая локальная копия не удаляется.

4. Проверьте скрипты и результат:

   ```bash
   python3 -m unittest discover -s tools/schedules/tests -v
   python3 tools/schedules/validate_schedule_data.py
   ```

5. Просмотрите и опубликуйте изменившийся `schedule-data/` вместе с обновлённым индексом. После публикации новые версии доступны всем пользователям без выпуска Android/iOS-релиза. Скрипты **не делают commit или push**.

## Текущее покрытие файлов

Индексы БРУ содержат группы и преподавателей, извлечённых только из сохранённых HTML-каталогов репозитория: 31 группа и 281 запись преподавателей. Из имеющихся локальных снимков расписание опубликовано для двух групп и одного преподавателя. Каталог БГУ пока содержит проверенный снимок группы Биофака 41; общего каталога преподавателей БГУ нет, поэтому группы и преподаватели добавляются через отдельные факультетские источники, без вымышленного общего URL. Наличие строки со статусом `missing` не означает, что у профиля уже есть доступное расписание.

Для новых университетов создайте папку реестра `tools/schedules/registry/<id>/`, добавьте строки в `universities.csv`, внесите отдельные индексы групп и преподавателей и запустите генератор. Чтобы вуз появился в выборе веб-версии без фонового запроса, добавьте `<option>` с его `id` в `web/index.html` и выпустите Pages. Университетские данные изолированы по `id` и не смешиваются.

## Доступ и безопасность

Приложение и PWA используют публичный HTTPS-адрес GitHub Pages (`https://konstantin-chvei.github.io/BRU-schedule/`). В клиент не встраиваются GitHub-токены: токен в приложении можно извлечь. Репозиторий сейчас закрытый; публикация Pages должна быть разрешена настройками/тарифом GitHub и выдавать сайт пользователям. Мы не меняли видимость репозитория. Если GitHub Pages в текущей конфигурации не доступен анонимно, владелец должен включить доступный вариант Pages либо опубликовать **только** статические данные и веб-сайт в публичном репозитории.
