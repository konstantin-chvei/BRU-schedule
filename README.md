# Расписание

Приложение для расписания занятий на Android и iOS, созданное на Kotlin Multiplatform и Compose Multiplatform. Для iPhone и iPad также доступна устанавливаемая PWA. Расписание и личные данные хранятся на устройстве; опубликованные файлы расписаний загружаются из GitHub только после действия пользователя.

## Возможности

- Расписания поддерживаемых групп и преподавателей.
- Локальная работа и офлайн-доступ после первой загрузки.
- Обновление по запросу с сохранением пользовательских пар, заметок, оценок и emoji-стикеров.
- Оценка каждой пары от 1 до 5 звёзд и выбор emoji-стикеров кнопкой «+».
- Календарь до окончания сессии плюс неделя; даты можно настроить для вуза или профиля.
- Ручные и повторяющиеся пары, обнаружение конфликтов, дедлайны и напоминания.
- Ежедневные сообщения из `content/daily-messages.txt`.

Клиенты не используют backend и не обращаются напрямую к сайтам вузов: Android и PWA читают опубликованные датасеты из `schedule-data` на GitHub Pages. Сайты вузов опрашиваются только во время явного обновления датасета через GitHub Actions.

## Если расписание в вузе обновилось

1. Убедитесь, что workflow `Import university schedule datasets` уже добавлен в основную ветку репозитория. GitHub показывает ручной запуск workflow, только когда файл workflow присутствует в default branch.
2. Откройте **Actions → Import university schedule datasets → Run workflow**. Для обновления GitHub Pages выберите ветку `master`; запуск на другой ветке публикует данные именно в неё.
3. Выберите `all`, `bru` или `bsu` и нажмите **Run workflow**. `all` обновляет оба вуза; выбор одного вуза не меняет датасет второго.
4. Дождитесь завершения. Импортёр повторно обнаружит опубликованные расписания, использует существующие KMP-парсеры и обновит CSV-файлы и индексы в `schedule-data`. Новые профили попадут туда только при наличии разобранных занятий. При временной сетевой ошибке прежний подтверждённый файл сохраняется.
5. В логе проверьте числа `discovered`, `imported`, `preserved` и `skipped`. Причины пропуска записываются в `schedule-data/import-report.json`. Если расписание на сайте перешло на новый формат и профиль не появился, не правьте сгенерированный CSV вручную: передайте ссылку на официальный источник или ZIP его HTML, чтобы обновить парсер и тестовый fixture, затем повторите workflow.

После коммита датасетов GitHub Pages развернётся автоматически. Переустанавливать Android-приложение или PWA не нужно: пользователь загружает свежий файл из GitHub обычным действием **«Обновить расписание»**. Пользовательские пары, заметки и оценки хранятся отдельно на устройстве. Workflow запускается вручную; фонового опроса сайтов вузов и backend нет.

## Android

Требуются JDK 21 и Android SDK Platform 37. Откройте корень репозитория в Android Studio и дождитесь Gradle Sync. Для локальной проверки выполните:

```bash
./gradlew :shared:allTests
./gradlew :androidApp:installDebug
```

Debug APK можно собрать командой `./gradlew :androidApp:assembleDebug`.

## iOS

### Нативное приложение

Для сборки нужны macOS, Xcode и JDK 21. Откройте `iosApp/iosApp.xcodeproj`, выберите схему `iosApp` и симулятор iPhone, затем запустите приложение кнопкой **Run**. Для установки на физическое устройство задайте Apple Team ID в `iosApp/Configuration/Config.xcconfig` и настройте подпись в Xcode. Bundle ID: `com.konstantinchvei.universalschedule`.

### Установка веб-версии на iPhone или iPad

Откройте в Safari опубликованный сайт: [Расписание](https://konstantin-chvei.github.io/BRU-schedule/). Нажмите **Поделиться → На экран Домой → Добавить**; если Safari предлагает переключатель **Открывать как веб-приложение**, включите его. Затем запускайте приложение с появившегося значка. Для офлайн-доступа сначала откройте приложение при подключении к интернету.

Полная инструкция доступна [на сайте](https://konstantin-chvei.github.io/BRU-schedule/ios-install.html) и по кнопке **«Установка на iPhone / iPad»** внутри веб-версии.
