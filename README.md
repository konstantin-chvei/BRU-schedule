# Schedule

Schedule помогает смотреть расписание занятий и держать под рукой важные учебные дела. Выберите группу или преподавателя, добавьте личные пары и заметки. После загрузки расписание можно открыть без интернета.

## Установка на iPhone и iPad через Safari

1. Откройте [Schedule](https://konstantin-chvei.github.io/Schedule/) в Safari. Если ссылка открылась во встроенном браузере Telegram или другого приложения, выберите **«Открыть в Safari»**.
2. Нажмите **«Поделиться»** — квадрат со стрелкой вверх.
3. В меню выберите **«На экран Домой»**. Если этого пункта нет, прокрутите список или добавьте его через **«Изменить действия»**.
4. Если появится настройка **«Открывать как веб-приложение»**, включите её и нажмите **«Добавить»**.
5. Запустите Schedule с нового значка на домашнем экране. Для первой загрузки расписания понадобится интернет; после этого сохранённое расписание будет доступно без сети.

## Запуск Android из Android Studio

Выберите общую конфигурацию запуска **Schedule Android** и синхронизируйте Gradle. Она запускает launcher activity, указанную в Android-манифесте, и берёт application ID из Gradle. Если Android Studio сообщает, что `com.example.bruschedule.MainActivity` не найдена, переключитесь со старой конфигурации с указанным вручную именем activity на **Schedule Android**. Kotlin namespace `com.example.bruschedule` и application ID `com.konstantinchvei.universalschedule` намеренно различаются; менять их не нужно.

## Ручное обновление каталога расписаний

Каталоги обновляются только вручную: в GitHub Actions запустите **Import university schedule datasets** и выберите `all`, `bru` или `bsu`. Приложение не опрашивает сайты вузов в фоне. Источники БГУ включают 16 факультетов и 11 учреждений образования из официальной структуры университета. Импортёр сохраняет обнаруженные профили БГУ во внутренний реестр `tools/schedules/registry/bsu/`; исходные URL остаются в этом реестре и не публикуются в пользовательском индексе. Профили, расписание которых сейчас недоступно, остаются в каталоге с соответствующим статусом.

Для БГУ импортёр пробует системный DNS и публичные DNS-резолверы; проверка TLS-сертификатов не отключается. После сетевой, DNS- или TLS-ошибки HTML-страницы повторно запрашиваются через Jina Reader (`X-Return-Format: html`); это происходит только в ручном импорте и передаёт публичный URL страницы стороннему сервису. При необходимости это можно отключить переменной `SCHEDULE_SOURCE_READER_FALLBACK=false`. Если GitHub runner не может напрямую подключиться к источникам, можно задать необязательный Actions secret `SCHEDULE_SOURCE_HTTP_PROXY` со значением `http://<proxy-ip>:<port>` (прокси без URL-логина и пароля). Перед тем как считать каталог полным, проверьте `schedule-data/import-report.json`: у всех ожидаемых источников должны быть `source_unavailable: false`, `request_failures: 0` и `crawl_truncated: false`; отдельно проверьте пропущенные профили и расписания со статусом `unavailable`. Если проверка полноты останавливает публикацию, workflow прикладывает артефакт `schedule-import-diagnostics-*` с отчётом и индексами для разбора.
